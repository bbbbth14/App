Embedded Systems Interview Questions & Answers

🔧 Embedded Systems Basics

What is an Embedded System?

An embedded system is a specialized computer system designed to perform dedicated functions within a larger mechanical or electrical system. Unlike general-purpose computers, embedded systems are optimized for specific tasks with constraints on size, power, and real-time performance. Examples include microwave ovens, automotive ECUs, medical devices, and smart watches.

What are the key characteristics of embedded systems?

Key characteristics include:
  • Task-specific: Designed for a particular application
  • Real-time operation: Must respond within strict timing constraints
  • Resource-constrained: Limited memory, processing power, and energy
  • Reliability: Must operate continuously without failure
  • Cost-sensitive: Optimized for mass production
  • Power efficiency: Often battery-powered or energy-constrained

What is the difference between a Microprocessor and a Microcontroller?

  • Microprocessor: Contains only the CPU. Requires external memory (RAM, ROM), I/O peripherals, and other components. Used in general-purpose computers.
  • Microcontroller: Contains CPU, memory (RAM, ROM/Flash), and peripherals (GPIO, ADC, timers, UART) all on a single chip. Ideal for embedded applications.
Microprocessor: CPU only → needs external components
Microcontroller: CPU + Memory + Peripherals → self-contained

Examples:
- Microprocessor: Intel Core i7, AMD Ryzen
- Microcontroller: ATmega328 (Arduino), STM32, ESP32

What is RTOS (Real-Time Operating System)?

An RTOS is an operating system designed to serve real-time applications that process data as it comes in, with strict timing constraints. It provides deterministic timing guarantees for task execution. 
Key features of RTOS:
- Task scheduling (preemptive/cooperative)
- Interrupt handling
- Inter-task communication (queues, semaphores)
- Memory management
- Timing services

Popular RTOS: FreeRTOS, VxWorks, QNX, Zephyr, RTLinux
⚡ Interrupts

What is an Interrupt?

An interrupt is a signal to the processor indicating an event that requires immediate attention. When an interrupt occurs, the processor suspends the current task, saves its state, executes an Interrupt Service Routine (ISR), then resumes the original task. 
Interrupt Flow:
1. Event triggers interrupt
2. CPU completes current instruction
3. CPU saves context (registers, PC)
4. CPU jumps to ISR (via interrupt vector)
5. ISR executes
6. CPU restores context
7. CPU resumes normal execution

What is the difference between Hardware and Software Interrupts?

  • Hardware Interrupt: Generated by external hardware devices (keyboard, timer, sensors). Asynchronous to program execution.
  • Software Interrupt: Triggered by software instructions (system calls, exceptions). Synchronous to program execution.
Hardware Interrupts:
- Timer overflow
- External pin change (GPIO)
- UART data received
- ADC conversion complete

Software Interrupts:
- Division by zero
- Invalid opcode
- System calls (SWI/SVC)

What is Interrupt Latency?

Interrupt latency is the time between when an interrupt is triggered and when the ISR begins execution. Minimizing interrupt latency is critical in real-time systems. 
Interrupt Latency = Recognition Time + Context Save Time + ISR Entry Time

Factors affecting latency:
- Current instruction completion time
- Pipeline flush time
- Context switching overhead
- Interrupt priority handling
- Cache misses

What is Interrupt Priority and Nested Interrupts?

Interrupt priority determines which interrupt is serviced first when multiple interrupts occur simultaneously. Nested interrupts allow a higher-priority interrupt to preempt a lower-priority ISR. 
Priority Levels (example):
- Level 0: Highest priority (e.g., NMI)
- Level 1: Timer interrupt
- Level 2: UART interrupt
- Level 3: Lowest priority

Nested Interrupt:
ISR_Low executing → High priority IRQ occurs
→ ISR_Low paused → ISR_High executes
→ ISR_High completes → ISR_Low resumes
💾 Memory & Storage

What are the different types of memory in embedded systems?

  • RAM (Volatile): SRAM (fast, expensive), DRAM (slower, cheaper)
  • ROM (Non-volatile): Mask ROM, PROM, EPROM, EEPROM
  • Flash: NOR Flash (code execution), NAND Flash (data storage)
  • Registers: Fastest memory, inside CPU
  • Cache: High-speed buffer between CPU and main memory
Memory Hierarchy (Fast to Slow):
Registers → Cache → SRAM → DRAM → Flash → External Storage

What is Memory-Mapped I/O vs Port-Mapped I/O?

  • Memory-Mapped I/O: I/O devices share the same address space as memory. Access using normal load/store instructions.
  • Port-Mapped I/O: I/O devices have a separate address space. Access using special I/O instructions (IN, OUT).
Memory-Mapped I/O (ARM, most modern MCUs):
volatile uint32_t *GPIO_PORT = (uint32_t *)0x40020000;
*GPIO_PORT = 0xFF;  // Write to GPIO

Port-Mapped I/O (x86):
outb(0x60, data);   // Write to port 0x60
data = inb(0x60);   // Read from port 0x60

What is the purpose of the volatile keyword in embedded C?

The volatile keyword tells the compiler that a variable's value may change unexpectedly (by hardware, ISR, or another thread), preventing optimization that could skip reading the actual value. 
// Without volatile - compiler may optimize away the loop
int *status_reg = (int *)0x40000000;
while (*status_reg == 0);  // May become infinite loop!

// With volatile - compiler always reads from memory
volatile int *status_reg = (volatile int *)0x40000000;
while (*status_reg == 0);  // Correctly checks hardware register

Use cases:
- Hardware registers
- Variables modified in ISR
- Shared variables in multi-threaded code
📡 Communication Protocols

Explain I2C (Inter-Integrated Circuit) protocol.

I2C is a synchronous, multi-master, multi-slave serial communication protocol using two wires: SDA (data) and SCL (clock). 
I2C Features:
- 2 wires: SDA (data), SCL (clock)
- Addressing: 7-bit or 10-bit slave addresses
- Speeds: Standard (100 kHz), Fast (400 kHz), Fast+ (1 MHz)
- Multi-master capable
- Open-drain outputs with pull-up resistors

Communication Flow:
1. START condition
2. Slave address + R/W bit
3. ACK from slave
4. Data transfer (8 bits + ACK)
5. STOP condition

Explain SPI (Serial Peripheral Interface) protocol.

SPI is a synchronous, full-duplex serial communication protocol using four wires. It's faster than I2C but requires more pins. 
SPI Signals:
- MOSI: Master Out, Slave In
- MISO: Master In, Slave Out
- SCLK: Serial Clock (from master)
- SS/CS: Slave Select (active low)

SPI Features:
- Full-duplex communication
- No addressing (uses chip select)
- Faster speeds (up to 50+ MHz)
- Simple protocol, no ACK
- 4 clock modes (CPOL, CPHA combinations)

Explain UART (Universal Asynchronous Receiver/Transmitter).

UART is an asynchronous serial communication protocol. Both devices must agree on baud rate, data bits, parity, and stop bits. 
UART Features:
- 2 wires: TX (transmit), RX (receive)
- Asynchronous (no clock line)
- Common baud rates: 9600, 115200
- Frame: Start bit + Data bits + Parity + Stop bit(s)

UART Frame (8N1):
|Start|D0|D1|D2|D3|D4|D5|D6|D7|Stop|
   0   ← 8 data bits →         1

Configuration: 115200 8N1
- 115200 baud
- 8 data bits
- No parity
- 1 stop bit

Compare I2C, SPI, and UART protocols.

| Feature      | I2C           | SPI            | UART          |
|--------------|---------------|----------------|---------------|
| Wires        | 2 (SDA, SCL)  | 4 (+ CS)       | 2 (TX, RX)    |
| Speed        | Up to 3.4 MHz | Up to 50+ MHz  | Up to 1 Mbps  |
| Duplex       | Half-duplex   | Full-duplex    | Full-duplex   |
| Addressing   | Yes (7/10-bit)| No (uses CS)   | No            |
| Multi-slave  | Yes           | Yes (via CS)   | Point-to-point|
| Clock        | Synchronous   | Synchronous    | Asynchronous  |
| Complexity   | Medium        | Low            | Low           |
🔌 GPIO & Peripherals

What is GPIO (General Purpose Input/Output)?

GPIO pins are digital pins on a microcontroller that can be configured as either input or output. They're used to interface with external devices like LEDs, buttons, sensors, and displays. 
GPIO Configuration:
- Input modes: Floating, Pull-up, Pull-down
- Output modes: Push-pull, Open-drain
- Alternate functions: UART, SPI, I2C, PWM

// Example: Toggle LED on GPIO
#define LED_PIN (1 << 5)
GPIO_PORT->DIR |= LED_PIN;     // Set as output
GPIO_PORT->DATA ^= LED_PIN;    // Toggle LED

What is PWM (Pulse Width Modulation)?

PWM is a technique to simulate analog output using digital signals by varying the duty cycle (ratio of ON time to total period). 
PWM Parameters:
- Frequency: How fast the signal toggles
- Duty Cycle: Percentage of ON time

Duty Cycle = (TON / Period) × 100%

Applications:
- LED dimming (50% duty = 50% brightness)
- Motor speed control
- Servo motor positioning
- Audio generation

Example: 1kHz PWM, 75% duty cycle
|‾‾‾‾‾‾‾‾‾‾‾‾|____|‾‾‾‾‾‾‾‾‾‾‾‾|____|
   750µs      250µs   750µs    250µs

What is ADC (Analog-to-Digital Converter)?

ADC converts continuous analog signals (voltage) to discrete digital values. Key parameters include resolution (bits), sampling rate, and reference voltage. 
ADC Parameters:
- Resolution: Number of bits (8, 10, 12, 16-bit)
- Sampling Rate: Samples per second
- Reference Voltage: Vref determines input range

Digital Value = (Vin / Vref) × (2^n - 1)

Example: 10-bit ADC, Vref = 3.3V, Vin = 1.65V
Digital Value = (1.65 / 3.3) × 1023 = 511

Types: SAR, Sigma-Delta, Flash, Pipeline
💻 Firmware & Programming

What is the Boot Process in embedded systems?

The boot process initializes the hardware and loads the application firmware when power is applied. 
Boot Sequence:
1. Power-on Reset (POR)
2. Hardware initialization (clock, memory)
3. Bootloader executes from ROM/Flash
4. Bootloader loads application to RAM (optional)
5. Jump to application entry point (main)
6. Application runs

Bootloader functions:
- Hardware initialization
- Firmware update capability
- Integrity checking
- Jump to application

What is a Watchdog Timer?

A watchdog timer (WDT) is a hardware timer that resets the system if not periodically "fed" (reset). It's used to recover from software hangs or crashes. 
Watchdog Operation:
1. WDT starts counting down
2. Software must reset WDT before timeout
3. If timeout occurs → System reset

// Watchdog usage pattern
void main() {
    WDT_init(1000);  // 1 second timeout
    while(1) {
        do_work();
        WDT_feed();  // Reset watchdog
    }
}

Use cases:
- Recover from infinite loops
- Detect hardware failures
- Safety-critical systems

What is DMA (Direct Memory Access)?

DMA allows peripherals to transfer data directly to/from memory without CPU intervention, improving performance and reducing CPU load. 
DMA Benefits:
- CPU free during data transfer
- Higher transfer speeds
- Lower power consumption (CPU can sleep)

DMA Transfer Types:
- Memory-to-Memory
- Peripheral-to-Memory
- Memory-to-Peripheral

Example: UART receiving 1KB data
Without DMA: CPU handles each byte interrupt
With DMA: CPU configures DMA once, gets interrupt when complete
🔥 Advanced Topics

What is Big Endian vs Little Endian?

Endianness refers to the order in which bytes are stored in memory. 
Value: 0x12345678

Big Endian (MSB first):
Address: 0x00  0x01  0x02  0x03
Data:    0x12  0x34  0x56  0x78

Little Endian (LSB first):
Address: 0x00  0x01  0x02  0x03
Data:    0x78  0x56  0x34  0x12

ARM: Usually Little Endian (configurable)
PowerPC: Usually Big Endian
Network protocols: Big Endian (network byte order)

What is the difference between polling and interrupt-driven I/O?

  • Polling: CPU continuously checks device status in a loop. Simple but wastes CPU cycles.
  • Interrupt-driven: CPU is notified by hardware when data is ready. More efficient, allows CPU to do other work.
Polling:
while (!(UART->STATUS & RX_READY));  // Waste cycles waiting
data = UART->DATA;

Interrupt-driven:
void UART_IRQHandler() {
    data = UART->DATA;  // Only called when data ready
}
// CPU can do other work or sleep

Explain the concept of bit manipulation in embedded systems.

Bit manipulation is essential for controlling hardware registers efficiently. 
Common Bit Operations:

// Set bit n
REG |= (1 << n);

// Clear bit n
REG &= ~(1 << n);

// Toggle bit n
REG ^= (1 << n);

// Check if bit n is set
if (REG & (1 << n))

// Set multiple bits (bits 2,3,4)
REG |= (0x07 << 2);

// Clear bits in a field, then set new value
REG = (REG & ~MASK) | NEW_VALUE;

// Example: Configure GPIO pin 5 as output, high
#define PIN5 (1 << 5)
GPIO->DIR |= PIN5;    // Set direction
GPIO->DATA |= PIN5;   // Set high

What is a Semaphore and Mutex in RTOS?

Both are synchronization primitives used in RTOS to manage shared resources. 
Mutex (Mutual Exclusion):
- Binary lock (0 or 1)
- Ownership: Only the task that locks can unlock
- Priority inheritance to prevent priority inversion
- Used for: Protecting shared resources

Semaphore:
- Counting or binary
- No ownership concept
- Can be signaled by any task
- Used for: Signaling, resource counting

// Mutex example
mutex_lock(&resource_mutex);
access_shared_resource();
mutex_unlock(&resource_mutex);

// Semaphore example (producer-consumer)
sem_wait(&items_available);  // Consumer waits
consume_item();
sem_post(&slots_available);  // Signal producer

What is Power Management in Embedded Systems?

Power management techniques are critical for battery-powered embedded devices. 
Power Saving Modes:
- Active: Full operation
- Idle/Sleep: CPU stopped, peripherals running
- Deep Sleep: Most peripherals off, RAM retained
- Shutdown: Only RTC/wakeup logic powered

Techniques:
- Clock gating: Disable unused peripheral clocks
- Voltage scaling: Lower voltage at lower frequencies
- Peripheral shutdown: Turn off unused I/O
- Duty cycling: Periodically wake for tasks

Example: IoT Sensor Node
1. Wake from deep sleep (RTC timer)
2. Read sensor, transmit data
3. Return to deep sleep
→ Average current: µA instead of mA
📝 Multiple Choice Questions

Which memory type is non-volatile?

  • A) SRAM
  • B) DRAM
  • C) Flash
  • D) Cache
Answer: C - Flash memory retains data without power. SRAM, DRAM, and Cache are volatile (lose data when power is off).

What is the main purpose of a watchdog timer?

  • A) Measure time intervals
  • B) Reset the system if software hangs
  • C) Generate PWM signals
  • D) Count external events
Answer: B - Watchdog timer automatically resets the system if not periodically "fed" by software, recovering from crashes or infinite loops.

How many wires does I2C use for communication?

  • A) 1
  • B) 2
  • C) 3
  • D) 4
Answer: B - I2C uses 2 wires: SDA (data) and SCL (clock). Both are bidirectional and require pull-up resistors.

Which protocol is asynchronous?

  • A) I2C
  • B) SPI
  • C) UART
  • D) CAN
Answer: C - UART is asynchronous (no clock line). I2C, SPI, and CAN all use a clock signal for synchronization.

What does PWM stand for?

  • A) Power Width Mode
  • B) Pulse Width Modulation
  • C) Pulse Wave Multiplexing
  • D) Power Wave Modulation
Answer: B - PWM stands for Pulse Width Modulation, a technique to control analog-like output using digital signals by varying the duty cycle.

In Little Endian format, how is 0x1234 stored in memory (starting at address 0)?

  • A) 0x12 at address 0, 0x34 at address 1
  • B) 0x34 at address 0, 0x12 at address 1
  • C) 0x12 at both addresses
  • D) 0x34 at both addresses
Answer: B - Little Endian stores the least significant byte (0x34) at the lowest address.

What is the purpose of DMA?

  • A) To increase CPU speed
  • B) To transfer data without CPU intervention
  • C) To manage memory allocation
  • D) To handle interrupts
Answer: B - DMA (Direct Memory Access) allows peripherals to transfer data directly to/from memory without CPU involvement, freeing the CPU for other tasks.

What keyword prevents compiler optimization for hardware registers in C?

  • A) static
  • B) const
  • C) volatile
  • D) extern
Answer: C - volatile tells the compiler that the variable may change unexpectedly, preventing optimization that could skip reading the actual value.

Which SPI signal carries data from master to slave?

  • A) MOSI
  • B) MISO
  • C) SCLK
  • D) SS
Answer: A - MOSI stands for Master Out, Slave In - it carries data from the master to the slave device.

What is the typical resolution of an ADC in embedded systems?

  • A) 1-4 bits
  • B) 8-16 bits
  • C) 32-64 bits
  • D) 128 bits
Answer: B - Common ADC resolutions are 8, 10, 12, or 16 bits. Higher resolution provides more precise measurements but requires more processing.

What is Interrupt Latency?

  • A) Time between two consecutive interrupts
  • B) Time from interrupt trigger to ISR start
  • C) Duration of ISR execution
  • D) Time to return from ISR
Answer: B - Interrupt latency is the delay between when an interrupt is triggered and when the Interrupt Service Routine (ISR) begins executing.

Which is NOT a characteristic of embedded systems?

  • A) Real-time operation
  • B) Resource constraints
  • C) General-purpose computing
  • D) Task-specific design
Answer: C - Embedded systems are designed for specific tasks, not general-purpose computing. They are optimized for particular applications with limited resources.
