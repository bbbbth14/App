📚 Basic Concepts

What is C programming language?

C is a general-purpose, procedural programming language developed by Dennis Ritchie at Bell Labs in 1972. It is one of the most widely used programming languages and has influenced many other languages like C++, Java, and Python. C is known for its efficiency, low-level memory access, and portability across different platforms.

What are the key features of C?

Key features of C include:
  • Simplicity: Easy to learn with a small set of keywords
  • Efficiency: Produces fast and efficient code
  • Portability: Programs can run on different platforms with minimal changes
  • Low-level access: Direct access to memory through pointers
  • Modularity: Supports functions for code reusability
  • Extensibility: Can add custom functions to libraries

What is the difference between #include <stdio.h> and #include "stdio.h"?

  • #include <stdio.h> - Searches for the header file in the standard system directories first
  • #include "stdio.h" - Searches for the header file in the current directory first, then in the standard system directories
Use angle brackets for standard library headers and double quotes for user-defined headers.
🔢 Data Types & Variables

What are the basic data types in C?

The basic data types in C are:
  • int - Integer numbers (typically 4 bytes)
  • char - Single character (1 byte)
  • float - Single precision floating-point (4 bytes)
  • double - Double precision floating-point (8 bytes)
  • void - Represents no value
These can be modified with short, long, signed, and unsigned.

What is the difference between const and #define?

  • #define is a preprocessor directive that creates a macro. It has no type and simply replaces text before compilation.
  • const creates a typed constant variable that exists in memory and has scope rules.
#define PI 3.14159    // Macro - no type checking
const double PI = 3.14159;  // Typed constant
const is generally preferred for type safety and debugging.
🎯 Pointers

What is a pointer in C?

A pointer is a variable that stores the memory address of another variable. Pointers are declared using the * operator and the address of a variable is obtained using the & operator. 
int num = 10;
int *ptr = &num;  // ptr stores the address of num
printf("%d", *ptr);  // Dereference: prints 10

What is a NULL pointer?

A NULL pointer is a pointer that points to nothing (address 0). It is used to indicate that the pointer is not pointing to any valid memory location. Always initialize pointers to NULL if they don't have a valid address yet. 
int *ptr = NULL;  // Good practice
if (ptr != NULL) {
    // Safe to dereference
}

What is the difference between *ptr++ and ++*ptr?

  • *ptr++ - Returns the value at ptr, then increments the pointer address
  • ++*ptr - Increments the value pointed to by ptr, then returns it
int arr[] = {10, 20, 30};
int *ptr = arr;
printf("%d\n", *ptr++);  // Prints 10, ptr now points to arr[1]
printf("%d\n", ++*ptr);  // Increments arr[1] to 21, prints 21
💾 Memory Management

What is the difference between malloc() and calloc()?

Both functions allocate memory dynamically, but with differences:
  • malloc(size) - Allocates specified bytes, memory contains garbage values
  • calloc(n, size) - Allocates memory for n elements of specified size, initializes to zero
// Allocate memory for 5 integers
int *arr1 = (int *)malloc(5 * sizeof(int));  // Not initialized
int *arr2 = (int *)calloc(5, sizeof(int));   // Initialized to 0

What is a memory leak?

A memory leak occurs when dynamically allocated memory is not freed after use. This causes the program to consume more memory over time, potentially leading to system slowdown or crashes. 
void leak_example() {
    int *ptr = (int *)malloc(sizeof(int));
    // Missing: free(ptr);
}  // Memory is leaked when function returns
Always use free() to release dynamically allocated memory.

What is the difference between stack and heap memory?

  • Stack: Used for static memory allocation (local variables, function calls). Memory is automatically managed (allocated/deallocated). Fast access but limited size.
  • Heap: Used for dynamic memory allocation (malloc, calloc). Programmer must manage memory manually. Slower access but larger size.
void example() {
    int stack_var = 10;  // Stack allocation
    int *heap_var = (int *)malloc(sizeof(int));  // Heap allocation
    *heap_var = 20;
    free(heap_var);  // Must free heap memory
}  // stack_var is automatically freed
📊 Arrays & Strings

What is the difference between an array and a pointer?

While arrays and pointers are closely related in C, they have key differences:
  • An array name is a constant pointer to the first element
  • sizeof(array) returns total array size, sizeof(pointer) returns pointer size
  • Array names cannot be reassigned; pointers can
int arr[5] = {1, 2, 3, 4, 5};
int *ptr = arr;
printf("%zu\n", sizeof(arr));  // 20 (5 * 4 bytes)
printf("%zu\n", sizeof(ptr));  // 8 (pointer size on 64-bit)

How do strings work in C?

In C, strings are arrays of characters terminated by a null character ('\0'). There is no built-in string type. 
char str1[] = "Hello";  // Compiler adds '\0' automatically
char str2[6] = {'H', 'e', 'l', 'l', 'o', '\0'};

// String functions from string.h
strlen(str1);      // Length (5)
strcpy(dest, src); // Copy string
strcmp(s1, s2);    // Compare strings
strcat(s1, s2);    // Concatenate strings
⚙️ Functions

What is the difference between call by value and call by reference?

  • Call by value: A copy of the argument is passed. Changes inside the function don't affect the original variable.
  • Call by reference: The address of the argument is passed. Changes inside the function affect the original variable.
void byValue(int x) { x = 100; }  // Original unchanged
void byReference(int *x) { *x = 100; }  // Original changed

int num = 10;
byValue(num);       // num is still 10
byReference(&num);  // num is now 100

What is a recursive function?

A recursive function is a function that calls itself to solve a problem by breaking it into smaller subproblems. Every recursive function needs a base case to stop the recursion. 
int factorial(int n) {
    if (n <= 1) return 1;  // Base case
    return n * factorial(n - 1);  // Recursive call
}
// factorial(5) = 5 * 4 * 3 * 2 * 1 = 120
🏗️ Structures & Unions

What is a structure in C?

A structure is a user-defined data type that groups related variables of different types under a single name. 
struct Student {
    char name[50];
    int age;
    float gpa;
};

struct Student s1 = {"John", 20, 3.5};
printf("Name: %s, Age: %d", s1.name, s1.age);

What is the difference between structure and union?

  • Structure: All members have their own memory locations. Size = sum of all member sizes (plus padding).
  • Union: All members share the same memory location. Size = size of largest member.
struct S { int i; char c; };  // Size: 8 bytes (with padding)
union U { int i; char c; };   // Size: 4 bytes (size of int)
Use unions when you need to store different types but only one at a time.
📁 File Handling

How do you read and write files in C?

C uses file pointers and functions from stdio.h for file operations: 
// Writing to a file
FILE *fp = fopen("data.txt", "w");
if (fp != NULL) {
    fprintf(fp, "Hello, World!");
    fclose(fp);
}

// Reading from a file
FILE *fp = fopen("data.txt", "r");
if (fp != NULL) {
    char buffer[100];
    while (fgets(buffer, 100, fp) != NULL) {
        printf("%s", buffer);
    }
    fclose(fp);
}
File modes: "r" (read), "w" (write), "a" (append), "r+" (read/write), "w+" (read/write, truncate).
🚀 Advanced Topics

What is a static variable?

A static variable retains its value between function calls. It is initialized only once and exists for the lifetime of the program. 
void counter() {
    static int count = 0;  // Initialized once
    count++;
    printf("Count: %d\n", count);
}
counter();  // Count: 1
counter();  // Count: 2
counter();  // Count: 3

What is the volatile keyword?

The volatile keyword tells the compiler that a variable's value may change unexpectedly (e.g., by hardware or another thread). This prevents the compiler from optimizing reads/writes to that variable. 
volatile int sensor_value;  // May change by hardware
// Compiler will always read from memory, not cache
Common uses: hardware registers, signal handlers, multi-threaded programming.

What is a function pointer?

A function pointer is a pointer that stores the address of a function. It can be used to call functions indirectly. 
int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }

int (*operation)(int, int);  // Function pointer declaration
operation = add;
printf("%d\n", operation(5, 3));  // Prints 8
operation = subtract;
printf("%d\n", operation(5, 3));  // Prints 2
Function pointers are useful for callbacks and implementing polymorphism in C.

What is the difference between ++i and i++?

  • ++i (pre-increment): Increments i first, then returns the new value
  • i++ (post-increment): Returns the current value of i, then increments it
int i = 5;
printf("%d\n", ++i);  // Prints 6, i is now 6
printf("%d\n", i++);  // Prints 6, i becomes 7
printf("%d\n", i);    // Prints 7
🔥 Expert Level Questions

What is a dangling pointer?

A dangling pointer is a pointer that references memory that has been freed or deallocated. Accessing a dangling pointer leads to undefined behavior. 
int *ptr = (int *)malloc(sizeof(int));
*ptr = 10;
free(ptr);      // Memory is freed
// ptr is now a dangling pointer
*ptr = 20;      // DANGEROUS: Undefined behavior

// Solution: Set pointer to NULL after freeing
free(ptr);
ptr = NULL;

What is pointer arithmetic?

Pointer arithmetic allows you to perform mathematical operations on pointers. When you add or subtract from a pointer, it moves by the size of the data type it points to. 
int arr[] = {10, 20, 30, 40, 50};
int *ptr = arr;

printf("%d\n", *ptr);       // 10
printf("%d\n", *(ptr + 1)); // 20
printf("%d\n", *(ptr + 2)); // 30

ptr++;  // Moves 4 bytes (sizeof(int))
printf("%d\n", *ptr);       // 20

What is the difference between realloc() and malloc()?

  • malloc() allocates a new block of memory
  • realloc() resizes an existing memory block, preserving the data
int *arr = (int *)malloc(5 * sizeof(int));
// arr has space for 5 integers

arr = (int *)realloc(arr, 10 * sizeof(int));
// arr now has space for 10 integers
// Original 5 values are preserved
If realloc fails, it returns NULL and the original memory is unchanged.

What is a void pointer?

A void pointer (void *) is a generic pointer that can hold the address of any data type. It must be cast to the appropriate type before dereferencing. 
void *ptr;
int num = 10;
float f = 3.14;

ptr = &num;
printf("%d\n", *(int *)ptr);    // Cast to int*

ptr = &f;
printf("%.2f\n", *(float *)ptr); // Cast to float*
Void pointers are commonly used in functions like malloc() and generic data structures.

What is a double pointer (pointer to pointer)?

A double pointer stores the address of another pointer. It's commonly used for dynamic 2D arrays and modifying pointer values in functions. 
int num = 10;
int *ptr = &num;
int **dptr = &ptr;

printf("%d\n", **dptr);  // 10

// Modifying pointer in function
void allocate(int **p) {
    *p = (int *)malloc(sizeof(int));
    **p = 100;
}

int *myPtr = NULL;
allocate(&myPtr);  // myPtr now points to allocated memory

What is the extern keyword?

The extern keyword declares a variable or function that is defined in another file. It tells the compiler that the definition exists elsewhere. 
// file1.c
int globalVar = 100;

// file2.c
extern int globalVar;  // Declaration, not definition
printf("%d\n", globalVar);  // Uses variable from file1.c
extern is essential for sharing variables across multiple source files.

What is the register keyword?

The register keyword suggests to the compiler that a variable should be stored in a CPU register for faster access. However, modern compilers often ignore this hint and optimize automatically. 
register int counter;
for (counter = 0; counter < 1000000; counter++) {
    // Fast loop variable
}
Note: You cannot take the address of a register variable using &.

What is a bit field in structures?

Bit fields allow you to specify the number of bits a structure member should occupy. They're useful for memory optimization and hardware programming. 
struct PackedData {
    unsigned int flag1 : 1;   // 1 bit
    unsigned int flag2 : 1;   // 1 bit
    unsigned int value : 6;   // 6 bits (0-63)
};  // Total: 1 byte instead of 12 bytes

struct PackedData data;
data.flag1 = 1;
data.flag2 = 0;
data.value = 42;

What is the difference between typedef and #define?

  • typedef creates an alias for a type, processed by the compiler with type checking
  • #define is a preprocessor macro that does text replacement
typedef int* IntPtr;
#define INT_PTR int*

IntPtr a, b;      // Both are int pointers
INT_PTR c, d;     // c is int*, d is just int!

// typedef is safer and more readable

What is an inline function?

An inline function suggests to the compiler to insert the function's code directly at the call site, avoiding function call overhead. 
inline int square(int x) {
    return x * x;
}

int result = square(5);
// Compiler may replace with: int result = 5 * 5;
Use inline for small, frequently called functions. The compiler may ignore the hint for complex functions.

What is recursion vs iteration? When to use which?

  • Recursion: Function calls itself. Elegant for tree/graph problems, but uses more memory (stack frames).
  • Iteration: Uses loops. More memory efficient, better for simple repetitive tasks.
// Recursion
int factorial_rec(int n) {
    return (n <= 1) ? 1 : n * factorial_rec(n - 1);
}

// Iteration
int factorial_iter(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) result *= i;
    return result;
}
Use recursion for naturally recursive problems (trees, backtracking). Use iteration for performance-critical code.

What is a segmentation fault?

A segmentation fault (segfault) occurs when a program tries to access memory it doesn't have permission to access. 
// Common causes:
int *ptr = NULL;
*ptr = 10;  // Dereferencing NULL pointer

int arr[5];
arr[10] = 1;  // Array index out of bounds

char *str = "Hello";
str[0] = 'h';  // Modifying string literal
Debug using tools like gdb or valgrind.

What is the difference between const char *ptr and char * const ptr?

  • const char *ptr - Pointer to a constant character. The data is constant, but the pointer can change.
  • char * const ptr - Constant pointer to a character. The pointer is constant, but the data can change.
  • const char * const ptr - Constant pointer to a constant character. Both are constant.
const char *ptr1 = "Hello";
ptr1 = "World";    // OK - pointer can change
*ptr1 = 'h';       // ERROR - data is constant

char * const ptr2 = str;
ptr2 = str2;       // ERROR - pointer is constant
*ptr2 = 'H';       // OK - data can change
Tip: Read from right to left: "ptr is a const pointer to char" vs "ptr is a pointer to const char".

What is function pointer and how is it used?

A function pointer stores the address of a function and can be used to call the function indirectly. Useful for callbacks and polymorphism in C. 
// Declaration: return_type (*pointer_name)(parameters)
int (*func_ptr)(int, int);

int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }

func_ptr = add;
printf("%d\n", func_ptr(5, 3));  // 8

func_ptr = subtract;
printf("%d\n", func_ptr(5, 3));  // 2

// Callback example
void execute(int (*operation)(int, int), int x, int y) {
    printf("Result: %d\n", operation(x, y));
}

execute(add, 10, 5);       // Result: 15
execute(subtract, 10, 5);  // Result: 5

Explain memory layout of a C program

A C program's memory is divided into several segments: 
High Address
┌─────────────────┐
│  Stack          │ ← Local variables, function parameters (grows down)
│       ↓         │
├─────────────────┤
│                 │
│  Free Space     │
│                 │
├─────────────────┤
│       ↑         │
│  Heap           │ ← Dynamic memory (malloc/calloc) (grows up)
├─────────────────┤
│  BSS Segment    │ ← Uninitialized global/static variables
├─────────────────┤
│  Data Segment   │ ← Initialized global/static variables
├─────────────────┤
│  Text Segment   │ ← Machine code (read-only)
└─────────────────┘
Low Address
  • Text: Program instructions (read-only, sharable)
  • Data: Initialized globals: int x = 10;
  • BSS: Uninitialized globals: int y;
  • Heap: Dynamic allocation: malloc()
  • Stack: Local variables, function calls

What is volatile keyword and when to use it?

The volatile keyword tells the compiler that a variable's value may change unexpectedly, preventing optimization. 
volatile int *hardware_register = (int *)0x40000000;

// Without volatile, compiler might optimize:
int x = *hardware_register;
int y = *hardware_register;  // Compiler: "x already has this value!"

// With volatile, compiler always reads from memory
volatile int x = *hardware_register;
volatile int y = *hardware_register;  // Always reads again
Use cases:
  • Memory-mapped hardware registers
  • Shared variables in multi-threaded programs
  • Variables modified by interrupt service routines (ISR)
  • Variables modified by signal handlers

What is the difference between macro and inline function?

Aspect Macro Inline Function
Processing Preprocessor (text replacement) Compiler
Type checking No type checking Type checking performed
Side effects Can cause issues (x++ evaluated multiple times) No side effects
Debugging Difficult Easier 
// Macro - dangerous with side effects
#define SQUARE(x) ((x) * (x))
int a = 5;
int b = SQUARE(a++);  // a++ * a++ = 5 * 6 = 30, a becomes 7!

// Inline function - safe
inline int square(int x) { return x * x; }
int c = 5;
int d = square(c++);  // c is incremented once, result = 25

What is structure padding and alignment?

Structure padding adds unused bytes between members to align data for efficient memory access. 
struct Example1 {
    char a;      // 1 byte
    // 3 bytes padding
    int b;       // 4 bytes
    char c;      // 1 byte
    // 3 bytes padding
};  // Total: 12 bytes (not 6!)

struct Example2 {
    char a;      // 1 byte
    char c;      // 1 byte
    // 2 bytes padding
    int b;       // 4 bytes
};  // Total: 8 bytes (optimized!)

// Check size
printf("%zu\n", sizeof(struct Example1));  // 12
printf("%zu\n", sizeof(struct Example2));  // 8

// Disable padding (use with caution!)
struct __attribute__((packed)) Packed {
    char a;
    int b;
    char c;
};  // Total: 6 bytes, but slower access
Tip: Order structure members from largest to smallest to minimize padding.

What is the difference between malloc and calloc?

  • malloc(size) - Allocates a single block of memory, uninitialized (contains garbage values)
  • calloc(count, size) - Allocates memory for an array, initializes all bytes to zero
// malloc - faster, but uninitialized
int *arr1 = (int *)malloc(5 * sizeof(int));
// arr1[0] might be 3456789 (garbage)

// calloc - slightly slower, but initialized to 0
int *arr2 = (int *)calloc(5, sizeof(int));
// arr2[0] is guaranteed to be 0

// Manual initialization with malloc
int *arr3 = (int *)malloc(5 * sizeof(int));
memset(arr3, 0, 5 * sizeof(int));  // Now same as calloc
When to use:
  • Use malloc when you'll immediately initialize the data
  • Use calloc when you need zero-initialized data (safer for pointers)

Explain restrict keyword in C

The restrict keyword (C99) tells the compiler that a pointer is the only way to access the data it points to, enabling optimization. 
// Without restrict - compiler assumes aliasing
void add_arrays(int *a, int *b, int *result, int n) {
    for (int i = 0; i < n; i++) {
        result[i] = a[i] + b[i];
        // Compiler must reload a[i] and b[i] each iteration
        // because result might point to same memory
    }
}

// With restrict - compiler knows no aliasing
void add_arrays_fast(int *restrict a, int *restrict b, 
                     int *restrict result, int n) {
    for (int i = 0; i < n; i++) {
        result[i] = a[i] + b[i];
        // Compiler can optimize: result doesn't alias a or b
    }
}
Benefits: Enables vectorization and better optimization
Warning: If you violate the restriction (pointers do overlap), behavior is undefined!

What is the difference between stack overflow and buffer overflow?

Stack Overflow: Occurs when the stack memory is exhausted, usually from deep/infinite recursion. 
// Stack overflow - too many function calls
void recursive() {
    int largeArray[10000];  // Each call uses 40KB
    recursive();            // Infinite recursion
}  // Crashes when stack space exhausted
Buffer Overflow: Occurs when data is written beyond the allocated buffer boundaries. 
// Buffer overflow - security vulnerability
char buffer[10];
strcpy(buffer, "This is a very long string");  // Overwrites adjacent memory!

// Safe version
char buffer[10];
strncpy(buffer, "This is a very long string", sizeof(buffer) - 1);
buffer[9] = '\0';  // Ensure null termination
Impact:
  • Stack overflow: Program crash (stack exhausted)
  • Buffer overflow: Memory corruption, security vulnerabilities (can be exploited by attackers)

How does setjmp and longjmp work?

setjmp and longjmp provide non-local goto capability for error handling and exception-like behavior. 
#include <setjmp.h>

jmp_buf jump_buffer;

void level3() {
    printf("Level 3\n");
    longjmp(jump_buffer, 42);  // Jump back to setjmp
    printf("Never executed\n");
}

void level2() {
    printf("Level 2\n");
    level3();
}

void level1() {
    printf("Level 1\n");
    level2();
}

int main() {
    int ret = setjmp(jump_buffer);  // Save execution context
    
    if (ret == 0) {
        printf("First call\n");
        level1();  // Call deep nested functions
    } else {
        printf("Returned via longjmp: %d\n", ret);  // 42
    }
    
    return 0;
}
Use cases: Error recovery, implementing exception handling, escaping from deeply nested calls
Warning: Can cause resource leaks (destructors not called), use with caution!

Explain memory-mapped I/O and how it's used in embedded systems

Memory-mapped I/O treats device registers as memory addresses, allowing direct hardware access. 
// Example: LED control on embedded device
#define LED_PORT    ((volatile unsigned int*)0x40020014)
#define LED_DDR     ((volatile unsigned int*)0x40020010)

// Configure LED pin as output
*LED_DDR |= (1 << 5);

// Turn LED on/off
*LED_PORT |= (1 << 5);   // LED ON
*LED_PORT &= ~(1 << 5);  // LED OFF

// Volatile is critical!
volatile unsigned int *reg = (unsigned int*)0x40001000;
while (*reg & 0x01);  // Wait for bit to clear
// Without volatile, compiler might optimize away the loop!
Why volatile is essential:
  • Prevents compiler optimization that caches values
  • Forces actual memory reads each time
  • Hardware can change values independently
  • Critical for MMIO, interrupts, multi-threading

What are compound literals and designated initializers in C99?

Compound Literals: Create unnamed array/struct objects on-the-fly. 
// Compound literal - creates temporary array
int sum(int arr[], int n) { /* ... */ }

// Call without creating named array
int result = sum((int[]){1, 2, 3, 4, 5}, 5);

// Struct compound literal
typedef struct { int x, y; } Point;
void print_point(Point p) { printf("%d,%d\n", p.x, p.y); }

print_point((Point){.x = 10, .y = 20});  // No temp variable needed!
Designated Initializers: Initialize specific members by name/index. 
// Array designated initializers
int arr[100] = {
    [0] = 1,
    [50] = 100,
    [99] = 200
    // Rest are 0
};

// Struct designated initializers
struct Config {
    char *name;
    int port;
    int timeout;
    int max_conn;
};

struct Config cfg = {
    .name = "Server",
    .port = 8080,
    .timeout = 30
    // max_conn defaults to 0
};

// Can mix with positional
int mixed[] = {1, 2, [5] = 6, 7};  // {1,2,0,0,0,6,7}
Benefits: Cleaner code, fewer bugs, self-documenting

Explain the different storage durations in C

C has 4 storage durations: automatic, static, allocated, and thread. 
// 1. AUTOMATIC (stack) - default for local variables
void func() {
    int x = 10;  // Created when func called, destroyed on return
    // Lifetime: function execution
}

// 2. STATIC - exists for program lifetime
int global = 5;  // File scope, static duration

void counter() {
    static int count = 0;  // Initialized once, persists between calls
    count++;
    printf("%d\n", count);
}

// 3. ALLOCATED (heap) - manual control
void heap_example() {
    int *ptr = malloc(sizeof(int));  // Exists until freed
    *ptr = 100;
    free(ptr);  // Must manually free
}

// 4. THREAD (_Thread_local in C11) - per-thread storage
_Thread_local int thread_var = 0;  // Each thread has own copy

// Storage class specifiers
auto int a;      // Automatic (rarely used, default for locals)
register int b;  // Hint for CPU register (obsolete)
static int c;    // Static duration + internal linkage
extern int d;    // Declaration, defined elsewhere
Memory segments:
  • Stack: Automatic variables, fast but limited size
  • Data: Initialized static/global (global = 10)
  • BSS: Uninitialized static/global (static int x;)
  • Heap: malloc/calloc/realloc, flexible but slower
  • Code: Executable instructions (read-only)

What is strict aliasing and why does it matter?

Strict aliasing rule: Accessing an object through incompatible pointer types is undefined behavior. 
// WRONG - Violates strict aliasing!
int i = 42;
float *fp = (float*)&i;  // Incompatible types
float f = *fp;  // Undefined behavior! Reads int as float

// Compiler assumes pointers to different types don't alias
void update(int *a, float *b) {
    *a = 10;
    *b = 20.0f;
    return *a;  // Compiler may optimize to return 10 directly
}
// If a and b actually point to same memory (aliased), result is wrong!

// CORRECT - Use union for type punning
union Convert {
    int i;
    float f;
};

union Convert c;
c.i = 42;
float result = c.f;  // Defined behavior via union
Exceptions (allowed aliasing):
  • char* can alias anything (byte access)

Explain sequence points and undefined behavior in expressions

Sequence points define when side effects of expressions must be complete. Between sequence points, order is undefined. 
// UNDEFINED - Multiple modifications without sequence point
int i = 5;
i = i++;  // UB! i modified twice without sequence point

int arr[10];
int j = 0;
arr[j] = j++;  // UB! j read and modified

// More subtle examples
int x = f() + g();  // UB if f() or g() modify same global
printf("%d %d\n", i++, i++);  // UB! Order of evaluation undefined

// DEFINED - Sequence points present
int a = 5;
a = a + 1;  // OK: Only one modification
a++;        // OK: Full expression is sequence point

int b = 5;
b = b + 1, b = b * 2;  // OK: Comma operator has sequence point
// First: b = 6, then: b = 12

// Logical operators have sequence points
if (ptr != NULL && *ptr == 5)  // OK: && guarantees left evaluated first

// Function calls have sequence points
printf("%d\n", i++);  // OK: i++ complete before printf processes args
Sequence points occur:
  • End of full expression (;)
  • After function arguments evaluated (before call)
  • After first operand of &&, ||, ?:, ,
  • Function return
// C11 sequencing (modernized)
// Instead of "sequence points", uses "sequenced before" relation
i = i++ + 1;  // Still UB in C11
i = (i + 1) + 1;  // OK
Best practice: One modification per variable per statement

What are the differences between malloc, calloc, and realloc?

malloc: Allocates memory without initialization. 
// malloc - fast but uninitialized (garbage values)
int *arr = (int*)malloc(10 * sizeof(int));
// arr[0..9] contain random garbage!
if (arr == NULL) { /* handle error */ }
free(arr);
calloc: Allocates and zeros memory. 
// calloc - slower but initialized to zero
int *arr = (int*)calloc(10, sizeof(int));
// arr[0..9] are all 0
// Syntax: calloc(count, size per element)
free(arr);
realloc: Resizes existing allocation. 
// realloc - resize dynamic array
int *arr = (int*)malloc(5 * sizeof(int));
// ... use arr[0..4] ...

// Need more space
int *temp = (int*)realloc(arr, 10 * sizeof(int));
if (temp == NULL) {
    // Realloc failed, arr still valid
    free(arr);
} else {
    arr = temp;  // arr now points to larger block
    // arr[0..4] preserved, arr[5..9] uninitialized
}

// realloc can move memory!
// Old arr pointer may be invalid after realloc
// Always assign to temp first
Performance comparison:
Function Speed Initial Value Use When
malloc Fastest Garbage Will initialize manually
calloc Slower Zero Need zero-initialized
realloc Varies Preserved + Garbage Resize existing array 
// realloc edge cases
int *p = malloc(100);
p = realloc(p, 200);  // WRONG! Memory leak if realloc fails

// Shrinking allocation
p = realloc(arr, 50);  // Make smaller, guaranteed success

// realloc with NULL = malloc
int *q = realloc(NULL, 100);  // Same as malloc(100)

// realloc with size 0 = free (implementation-defined)
realloc(arr, 0);  // May free and return NULL

How does offsetof macro work and when should you use it?

offsetof returns the byte offset of a struct member from the start of the struct. 
#include <stddef.h>

struct Employee {
    int id;          // Offset: 0
    char name[50];   // Offset: 4
    double salary;   // Offset: 56 (with padding)
};

// Get offsets
size_t id_offset = offsetof(struct Employee, id);        // 0
size_t name_offset = offsetof(struct Employee, name);    // 4
size_t salary_offset = offsetof(struct Employee, salary);  // 56

printf("ID at offset: %zu\n", id_offset);
printf("Name at offset: %zu\n", name_offset);
printf("Salary at offset: %zu\n", salary_offset);

// Container_of macro (Linux kernel pattern)
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

struct Employee emp = {123, "John", 50000.0};
char *name_ptr = emp.name;

// Get struct pointer from member pointer
struct Employee *emp_ptr = container_of(name_ptr, struct Employee, name);
printf("ID: %d\n", emp_ptr->id);  // 123

// Use case: Intrusive linked lists
struct Node {
    int data;
    struct Node *next;
};

struct Container {
    char tag[10];

    int value;
};

  • Implement intrusive containers
  • Serialize/deserialize structures
  • Network protocol parsing
  • Reflection-like capabilities in C

Explain the differences between signed and unsigned integer overflow

Unsigned overflow: Well-defined, wraps around (modulo 2^n). 
// Unsigned overflow is DEFINED behavior
unsigned int u = UINT_MAX;  // 4294967295 (on 32-bit)
u++;  // Wraps to 0 (guaranteed)
u--;  // Wraps to UINT_MAX

// Safe for certain algorithms
unsigned int hash = 0;
for (int i = 0; i < n; i++) {
    hash = hash * 31 + data[i];  // Overflow is OK, wraps predictably
}

// Time calculations
unsigned int start = get_time();
// ... work ...
unsigned int end = get_time();
unsigned int elapsed = end - start;  // Correct even if timer wrapped!
Signed overflow: Undefined behavior! 
// Signed overflow is UNDEFINED BEHAVIOR
int i = INT_MAX;  // 2147483647
i++;  // UB! Anything can happen

// Compiler can assume no overflow occurred
int dangerous(int x) {
    return x + 1 > x;  // Should always be true, right?
}
// Optimizer sees "x+1 can't overflow" and returns true without computing!
// dangerous(INT_MAX) may return true even though INT_MAX+1 <= INT_MAX

// Real bug example
int len = strlen(input);
char *buf = malloc(len + 1);  // If len = INT_MAX, allocates 0 bytes!

// Security vulnerabilities
int size = width * height;  // Overflow! Allocates too little
void *buffer = malloc(size);
Safe overflow checking: 
// Check before operation
int safe_add(int a, int b, int *result) {
    if (a > 0 && b > INT_MAX - a) return -1;  // Would overflow
    if (a < 0 && b < INT_MIN - a) return -1;  // Would underflow
    *result = a + b;
    return 0;
}

// GCC built-ins (C5+)
int a, b, result;
if (__builtin_add_overflow(a, b, &result)) {
    // Overflow occurred
} else {
    // result is valid
}

// Use unsigned when wrapping is desired
unsigned int counter = 0;
counter--;  // Wraps to UINT_MAX (defined behavior)
Consequences of UB:
  • Compiler can optimize assuming no overflow
  • Different results with -O0 vs -O2
  • Security vulnerabilities (buffer overruns)
  • Unpredictable behavior across platforms

What is the purpose of flexible array members in structs?

Flexible array members (FAM) allow variable-size arrays as the last member of a struct (C99+). 
// Traditional (pre-C99) - "struct hack"
struct OldString {
    size_t length;
    char data[1];  // Actually allocated larger
};

struct OldString *s = malloc(sizeof(*s) + 100);  // Allocate for 100 chars
s->length = 100;
strcpy(s->data, "Hello");  // Works but technically UB

// Modern C99 - Flexible Array Member
struct String {
    size_t length;
    char data[];  // FAM - no size specified!
};

// Allocate string with 100 characters
struct String *str = malloc(sizeof(struct String) + 100);
str->length = 100;
strcpy(str->data, "Hello, World!");
printf("%s\n", str->data);
free(str);

// sizeof behavior
printf("%zu\n", sizeof(struct String));  // Doesn't include data[]

// Real-world example: Network packet
struct Packet {
    uint32_t type;
    uint32_t length;
    uint8_t payload[];  // Variable-length payload
};

// Allocate packet with specific payload size
size_t payload_size = 1024;
struct Packet *pkt = malloc(sizeof(struct Packet) + payload_size);
pkt->type = PKT_DATA;
pkt->length = payload_size;
memcpy(pkt->payload, data, payload_size);

// Send packet
send(sock, pkt, sizeof(struct Packet) + pkt->length, 0);
free(pkt);
Rules for FAM:
  • Must be last member of struct
  • Struct must have at least one other member
  • Cannot have array of such structs
  • sizeof(struct) doesn't include FAM
// Incorrect uses
struct Bad1 {
    char data[];  // ERROR: No other members
};

struct Bad2 {
    char data[];
    int x;  // ERROR: FAM not last
};

struct Good {
    int count;
    double values[];  // OK
};

// Cannot create array of FAM structs
struct Good arr[10];  // ERROR!
Benefits: Single allocation (better cache locality), proper semantics (vs struct hack)

How do you implement generic data structures in C?

C provides several approaches for generic programming: void pointers, macros, and code generation. 
// 1. VOID POINTERS - Type-agnostic, runtime overhead
typedef struct {
    void **data;
    size_t size;
    size_t capacity;
    size_t elem_size;
} Vector;

void vector_init(Vector *v, size_t elem_size) {
    v->data = malloc(10 * sizeof(void*));
    v->size = 0;
    v->capacity = 10;
    v->elem_size = elem_size;
}

void vector_push(Vector *v, void *elem) {
    if (v->size >= v->capacity) {
        v->capacity *= 2;
        v->data = realloc(v->data, v->capacity * sizeof(void*));
    }
    v->data[v->size] = malloc(v->elem_size);
    memcpy(v->data[v->size], elem, v->elem_size);
    v->size++;
}

void* vector_get(Vector *v, size_t index) {
    return v->data[index];
}

// Usage
Vector int_vec;
vector_init(&int_vec, sizeof(int));
int x = 42;
vector_push(&int_vec, &x);
int *retrieved = (int*)vector_get(&int_vec, 0);

// 2. MACROS - Type-safe, compile-time
#define DECLARE_VECTOR(type) \
    typedef struct { \
        type *data; \
        size_t size; \
        size_t capacity; \
    } Vector_##type; \
    \
    void Vector_##type##_init(Vector_##type *v) { \
        v->data = malloc(10 * sizeof(type)); \
        v->size = 0; \
        v->capacity = 10; \
    } \
    \
    void Vector_##type##_push(Vector_##type *v, type elem) { \
        if (v->size >= v->capacity) { \
            v->capacity *= 2; \
            v->data = realloc(v->data, v->capacity * sizeof(type)); \
        } \
        v->data[v->size++] = elem; \
    } \
    \
    type Vector_##type##_get(Vector_##type *v, size_t i) { \
        return v->data[i]; \
    }

// Instantiate for int
DECLARE_VECTOR(int)
DECLARE_VECTOR(double)

// Usage
Vector_int vec;
Vector_int_init(&vec);
Vector_int_push(&vec, 42);
int val = Vector_int_get(&vec, 0);  // Type-safe!

// 3. GENERIC COMPARISON FUNCTIONS (qsort style)
void generic_swap(void *a, void *b, size_t size) {
    unsigned char temp[size];
    memcpy(temp, a, size);
    memcpy(a, b, size);
    memcpy(b, temp, size);
}

void generic_sort(void *base, size_t nmemb, size_t size,
                  int (*cmp)(const void*, const void*)) {
    for (size_t i = 0; i < nmemb-1; i++) {
        for (size_t j = 0; j < nmemb-i-1; j++) {
            void *p1 = (char*)base + j*size;
            void *p2 = (char*)base + (j+1)*size;
            if (cmp(p1, p2) > 0) {
                generic_swap(p1, p2, size);
            }
        }
    }
}

// Comparison functions
int compare_int(const void *a, const void *b) {
    return *(int*)a - *(int*)b;
}

int arr[] = {5, 2, 8, 1, 9};
generic_sort(arr, 5, sizeof(int), compare_int);
Trade-offs:
  • Void pointers: Flexible but not type-safe, runtime overhead
  • Macros: Type-safe, fast, but code bloat and ugly syntax
  • Code generation: Best of both, requires build step

Explain how sigsetjmp and siglongjmp differ from regular setjmp/longjmp

sigsetjmp/siglongjmp additionally save and restore the signal mask, making them signal-safe. 
#include <setjmp.h>
#include <signal.h>

// Regular setjmp/longjmp - signal mask may change
jmp_buf env;

void signal_handler(int sig) {
    longjmp(env, 1);  // Jump back
}

void example_unsafe() {
    signal(SIGINT, signal_handler);
    
    if (setjmp(env) == 0) {
        // Block SIGINT
        sigset_t set;
        sigemptyset(&set);
        sigaddset(&set, SIGINT);
        sigprocmask(SIG_BLOCK, &set, NULL);
        
        // Do work... if signal arrives and longjmp executes,
        // SIGINT remains blocked! (signal mask not restored)
    }
}

// sigsetjmp/siglongjmp - restores signal mask
sigjmp_buf sigenv;

void safe_handler(int sig) {
    siglongjmp(sigenv, 1);  // Restores signal mask!
}

void example_safe() {
    signal(SIGINT, safe_handler);
    
    if (sigsetjmp(sigenv, 1) == 0) {  // 1 = save signal mask
        // Block SIGINT
        sigset_t set;
        sigemptyset(&set);
        sigaddset(&set, SIGINT);
        sigprocmask(SIG_BLOCK, &set, NULL);
        
        // Do work... if signal arrives and siglongjmp executes,
        // signal mask is restored to what it was at sigsetjmp
    }
    // Signal mask restored here
}

// Error recovery in signal handlers
volatile sig_atomic_t error_occurred = 0;
sigjmp_buf recover_point;

void fault_handler(int sig) {
    error_occurred = 1;
    siglongjmp(recover_point, 1);
}

int safe_operation(int *ptr) {
    signal(SIGSEGV, fault_handler);
    
    if (sigsetjmp(recover_point, 1) == 0) {
        // Try potentially dangerous operation
        int value = *ptr;  // May fault if ptr is invalid
        return value;
    } else {
        // Recovered from SIGSEGV
        return -1;
    }
}

// Usage
int *bad_ptr = NULL;
int result = safe_operation(bad_ptr);  // Returns -1 instead of crashing
Key differences:
Feature setjmp/longjmp sigsetjmp/siglongjmp
Signal mask Not saved Optionally saved (if savemask != 0)
Use in signal handlers Unsafe Safe
Performance Slightly faster Slightly slower
When to use: Use sigsetjmp/siglongjmp when jumping from signal handlers or when signal mask preservation is critical

What are the pitfalls of using gets() and how does fgets() solve them?

gets() is dangerous and removed from C11 due to buffer overflow vulnerabilities. 
// NEVER USE gets() - it's dangerous!
char buffer[10];
gets(buffer);  // No bounds checking!
// If user types more than 9 characters, buffer overflow!
// Removed from C11 standard

// ALWAYS USE fgets() instead
char buffer[10];
if (fgets(buffer, sizeof(buffer), stdin) != NULL) {
    // Safe: reads at most sizeof(buffer)-1 chars
    // Includes newline if present
    
    // Remove trailing newline
    size_t len = strlen(buffer);
    if (len > 0 && buffer[len-1] == '\n') {
        buffer[len-1] = '\0';
    }
}

// Better: handle long inputs
void read_line(char *buffer, size_t size) {
    if (fgets(buffer, size, stdin) == NULL) {
        buffer[0] = '\0';  // Error or EOF
        return;
    }
    
    // Remove newline
    size_t len = strlen(buffer);
    if (len > 0 && buffer[len-1] == '\n') {
        buffer[len-1] = '\0';
    } else {
        // Input was truncated, discard rest of line
        int c;
        while ((c = getchar()) != '\n' && c != EOF);
    }
}

// Even better: dynamic allocation
char* read_line_dynamic(void) {
    char *line = NULL;
    size_t size = 0;
    ssize_t len = getline(&line, &size, stdin);  // POSIX, not C standard
    
    if (len > 0 && line[len-1] == '\n') {
        line[len-1] = '\0';
    }
    
    return line;  // Caller must free()
}

// Usage
char *input = read_line_dynamic();
if (input) {
    printf("You entered: %s\n", input);
    free(input);
}

// Comparison
char buf[100];

// DANGEROUS - buffer overflow
gets(buf);

// SAFE - bounds checked
fgets(buf, sizeof(buf), stdin);

// SAFE - specified size
fgets(buf, 100, stdin);

// SAFE - portable dynamic input (C11)
#include <stdio.h>
char buffer[256];
if (scanf("%255s", buffer) == 1) {  // Leave space for \0
    printf("Got: %s\n", buffer);
}
Why gets() is dangerous:
  • No way to limit input size
  • Guaranteed buffer overflow with long input
  • Primary cause of security vulnerabilities
  • Exploitable for arbitrary code execution
Alternatives comparison:
Function Safety Newline Standard

fgets() ✅ Safe Kept C89+
gets_s() ✅ Safe Removed C11 (optional)

How do you properly handle endianness in network programming?

Endianness refers to byte order: little-endian (LSB first) vs big-endian (MSB first). Networks use big-endian. 
// Endianness example
uint32_t value = 0x12345678;

// Little-endian (x86): 78 56 34 12 in memory
// Big-endian (network): 12 34 56 78 in memory

// Convert host ↔ network byte order
#include <arpa/inet.h>  // POSIX
#include <netinet/in.h>

uint32_t host_value = 0x12345678;
uint32_t net_value = htonl(host_value);  // Host TO Network Long
uint32_t back = ntohl(net_value);        // Network TO Host Long

uint16_t port = 8080;
uint16_t net_port = htons(port);  // Host TO Network Short
uint16_t host_port = ntohs(net_port);

// Sending over network
struct Packet {
    uint32_t type;
    uint32_t length;
    uint16_t port;
    char data[100];
};

void send_packet(int sock, struct Packet *pkt) {
    struct Packet net_pkt;
    net_pkt.type = htonl(pkt->type);
    net_pkt.length = htonl(pkt->length);
    net_pkt.port = htons(pkt->port);
    memcpy(net_pkt.data, pkt->data, sizeof(pkt->data));
    
    send(sock, &net_pkt, sizeof(net_pkt), 0);
}

void recv_packet(int sock, struct Packet *pkt) {
    struct Packet net_pkt;
    recv(sock, &net_pkt, sizeof(net_pkt), 0);
    
    pkt->type = ntohl(net_pkt.type);
    pkt->length = ntohl(net_pkt.length);
    pkt->port = ntohs(net_pkt.port);
    memcpy(pkt->data, net_pkt.data, sizeof(net_pkt.data));
}

// Detect endianness at runtime
int is_little_endian(void) {
    uint32_t test = 1;
    return *(uint8_t*)&test == 1;
}

// Portable byte swap
uint32_t swap32(uint32_t x) {
    return ((x & 0xFF000000) >> 24) |
           ((x & 0x00FF0000) >> 8)  |
           ((x & 0x0000FF00) << 8)  |
           ((x & 0x000000FF) << 24);
}

uint16_t swap16(uint16_t x) {
    return (x >> 8) | (x << 8);
}

// Conditional swap based on endianness
uint32_t to_big_endian(uint32_t x) {
    if (is_little_endian()) {
        return swap32(x);
    }
    return x;
}

// Reading binary file with specific endianness
void read_binary_file(const char *filename) {
    FILE *fp = fopen(filename, "rb");
    uint32_t value;
    
    fread(&value, sizeof(value), 1, fp);
    
    // File is always big-endian
    #if __BYTE_ORDER__ == __ORDER_LITTLE_ENDIAN__
        value = swap32(value);
    #endif
    
    printf("Value: 0x%08X\n", value);
    fclose(fp);
}
Endianness functions:
  • htonl() - Host TO Network Long (32-bit)
  • htons() - Host TO Network Short (16-bit)
  • ntohl() - Network TO Host Long
  • ntohs() - Network TO Host Short
Best practices: Always convert to network byte order before sending, convert back after receiving

  • C) <!-- comment -->
  • D) # comment #
Answer: B - Multi-line comments use /* */. Single-line comments use // (C99 and later).

What is the result of: int a = 5, b = 2; float c = a / b;

  • A) c = 2.0
  • B) c = 2.5
  • C) c = 2
  • D) Compilation error
Answer: A - Integer division happens first (5/2 = 2), then the result is converted to float (2.0). For 2.5, cast one operand: (float)a / b.

Which operator is used to access a structure member through a pointer?

  • A) . (dot)
  • B) -> (arrow)
  • C) * (asterisk)
  • D) & (ampersand)
Answer: B - The arrow operator (->) is used with pointers to structures. Dot (.) is used with structure variables directly.
