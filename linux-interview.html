🐧 Linux Basics

What is Linux?

Linux is a free, open-source, Unix-like operating system kernel created by Linus Torvalds in 1991. It forms the core of many operating systems (distributions) like Ubuntu, Fedora, Debian, and Android. Linux is known for its stability, security, and flexibility. 
Key characteristics:
- Open source (GPL license)
- Multi-user and multi-tasking
- Portable across hardware platforms
- Strong security model
- Extensive networking support
- Command-line interface (shell)

What is the difference between Linux Kernel and Linux Distribution?

  • Linux Kernel: The core of the OS that manages hardware, memory, processes, and system calls. It's the actual "Linux" created by Linus Torvalds.
  • Linux Distribution: A complete OS package containing the kernel plus utilities, libraries, GUI, package manager, and applications.
Kernel: linux-5.15.0
         ↓
Distribution: Ubuntu 22.04
├── Kernel (linux-5.15)
├── GNU utilities (bash, coreutils)
├── Package manager (apt)
├── Desktop environment (GNOME)
├── System services (systemd)
└── Applications (Firefox, LibreOffice)

Explain the Linux boot process.

The Linux boot process involves several stages from power-on to user login: 
1. BIOS/UEFI
   - POST (Power-On Self Test)
   - Locate and load bootloader

2. Bootloader (GRUB)
   - Load kernel and initramfs into memory
   - Pass control to kernel

3. Kernel Initialization
   - Decompress and initialize
   - Mount initramfs as temporary root
   - Initialize hardware drivers
   - Mount real root filesystem

4. Init System (systemd/init)
   - First userspace process (PID 1)
   - Start system services
   - Set runlevel/target

5. Login
   - Display login prompt (getty/display manager)
   - User authentication

What are User Space and Kernel Space?

Linux divides memory into two distinct regions for security and stability:
  • Kernel Space: Protected memory area where the kernel executes. Has full access to hardware and all memory. Only kernel code runs here.
  • User Space: Where user applications run. Restricted access - cannot directly access hardware or kernel memory. Must use system calls to request kernel services.
Virtual Memory Layout (32-bit):
┌─────────────────┐ 0xFFFFFFFF
│   Kernel Space  │ (1GB)
│   (Protected)   │
├─────────────────┤ 0xC0000000
│                 │
│   User Space    │ (3GB)
│  (Applications) │
│                 │
└─────────────────┘ 0x00000000

Communication: System Calls (syscall)

What is a System Call?

A system call is the interface between user space and kernel space. Applications use syscalls to request services from the kernel (file I/O, process management, networking, etc.). 
Common System Calls:
- open(), read(), write(), close()  // File I/O
- fork(), exec(), exit(), wait()    // Process
- socket(), connect(), send()       // Networking
- mmap(), brk()                     // Memory

Example flow:
User App → printf("Hello")
         → write() syscall
         → Kernel handles I/O
         → Returns to user space

// Syscall invocation (x86-64)
mov rax, 1        // syscall number (write)
mov rdi, 1        // fd (stdout)
mov rsi, msg      // buffer
mov rdx, len      // length
syscall           // trigger syscall

What is the /proc filesystem?

The /proc filesystem is a virtual filesystem that provides an interface to kernel data structures. It doesn't exist on disk - files are generated dynamically by the kernel. 
Important /proc entries:
/proc/cpuinfo      # CPU information
/proc/meminfo      # Memory statistics
/proc/interrupts   # IRQ usage
/proc/devices      # Registered devices
/proc/modules      # Loaded kernel modules
/proc/cmdline      # Kernel boot parameters
/proc/version      # Kernel version
/proc/[PID]/       # Per-process info
  ├── status       # Process status
  ├── maps         # Memory mappings
  ├── fd/          # File descriptors
  └── cmdline      # Command line args

🔧 Linux Device Drivers

What is a Linux Device Driver?

A device driver is kernel code that controls a hardware device. It provides a standard interface between the hardware and the kernel/applications. 
Driver responsibilities:
- Initialize and configure hardware
- Handle data transfer (read/write)
- Manage interrupts
- Implement power management
- Provide user-space interface

Types of drivers:
1. Character drivers (char dev)
   - Sequential access (byte stream)
   - Examples: serial ports, keyboards

2. Block drivers (block dev)
   - Random access (blocks)
   - Examples: hard drives, SSDs

3. Network drivers
   - Packet-based communication
   - Examples: Ethernet, WiFi adapters

Explain the structure of a basic Linux kernel module.

#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("Simple module");
MODULE_VERSION("1.0");

// Called when module is loaded
static int __init my_init(void)
{
    printk(KERN_INFO "Hello, Kernel!\n");
    return 0;  // 0 = success
}

// Called when module is unloaded
static void __exit my_exit(void)
{
    printk(KERN_INFO "Goodbye, Kernel!\n");
}

module_init(my_init);
module_exit(my_exit);

// Build commands:
// make -C /lib/modules/$(uname -r)/build M=$(PWD) modules
// sudo insmod mymodule.ko   # Load
// sudo rmmod mymodule       # Unload
// dmesg | tail              # View messages

What are Character Device Drivers?

Character devices transfer data as a stream of bytes (character by character). They're accessed through device files in /dev. 
Character Driver Components:

1. Device Numbers (Major:Minor)
   - Major: Identifies the driver
   - Minor: Identifies specific device

2. File Operations Structure:
struct file_operations fops = {
    .owner   = THIS_MODULE,
    .open    = device_open,
    .release = device_release,
    .read    = device_read,
    .write   = device_write,
    .unlocked_ioctl = device_ioctl,
};

3. Registration:
// Allocate device numbers
alloc_chrdev_region(&dev_num, 0, 1, "mydevice");

// Initialize and add cdev
cdev_init(&my_cdev, &fops);
cdev_add(&my_cdev, dev_num, 1);

// Create device file
class_create(THIS_MODULE, "myclass");
device_create(my_class, NULL, dev_num, NULL, "mydev");

// Access from user space:
// sudo mknod /dev/mydev c 240 0
// cat /dev/mydev
// echo "data" > /dev/mydev

Explain the file_operations structure.

The file_operations structure defines the functions a driver implements to handle file operations on a device. 
struct file_operations {
    struct module *owner;
    
    // File open/close
    int (*open)(struct inode *, struct file *);
    int (*release)(struct inode *, struct file *);
    
    // Data transfer
    ssize_t (*read)(struct file *, char __user *, 
                    size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *, 
                     size_t, loff_t *);
    
    // Seek position
    loff_t (*llseek)(struct file *, loff_t, int);
    
    // Device control
    long (*unlocked_ioctl)(struct file *, 
                           unsigned int, unsigned long);
    
    // Memory mapping
    int (*mmap)(struct file *, struct vm_area_struct *);
    
    // Polling/select
    unsigned int (*poll)(struct file *, 
                         struct poll_table_struct *);
};

// User space call → Driver function:
open()  → .open
close() → .release
read()  → .read
write() → .write
ioctl() → .unlocked_ioctl

How do you transfer data between User Space and Kernel Space?

Direct memory access between kernel and user space is not allowed. Special functions must be used: 
// Copy from user space to kernel
unsigned long copy_from_user(void *to, 
                             const void __user *from, 
                             unsigned long n);

// Copy from kernel to user space
unsigned long copy_to_user(void __user *to, 
                           const void *from, 
                           unsigned long n);

// Single value transfer
get_user(kernel_var, user_ptr);
put_user(kernel_val, user_ptr);

// Example: read function
static ssize_t dev_read(struct file *filp, 
                        char __user *buf,
                        size_t len, loff_t *off)
{
    char kernel_buf[] = "Hello from kernel";
    int bytes = strlen(kernel_buf);
    
    if (copy_to_user(buf, kernel_buf, bytes))
        return -EFAULT;
    
    return bytes;
}

// Returns 0 on success, non-zero = bytes not copied
⚡ Interrupts & Concurrency

How do you handle interrupts in Linux drivers?

// Request an IRQ
int request_irq(unsigned int irq,
                irq_handler_t handler,
                unsigned long flags,
                const char *name,
                void *dev_id);

// IRQ handler function
static irqreturn_t my_irq_handler(int irq, void *dev_id)
{
    // Handle interrupt (minimal work)
    // Schedule bottom half for heavy work
    
    return IRQ_HANDLED;  // or IRQ_NONE
}

// Free IRQ on cleanup
free_irq(irq, dev_id);

// IRQ flags:
IRQF_SHARED     // Shared interrupt line
IRQF_TRIGGER_RISING   // Rising edge trigger
IRQF_TRIGGER_FALLING  // Falling edge trigger

// Top Half vs Bottom Half:
// Top Half: Runs in interrupt context (fast, no sleep)
// Bottom Half: Deferred work (tasklets, workqueues)

What are Tasklets and Workqueues?

Both are mechanisms for deferring work from interrupt handlers (bottom half processing): 
TASKLETS:
- Run in software interrupt context
- Cannot sleep
- Fast, low overhead

DECLARE_TASKLET(my_tasklet, tasklet_fn, data);

void tasklet_fn(unsigned long data) {
    // Deferred work (can't sleep)
}

// Schedule from ISR
tasklet_schedule(&my_tasklet);


WORKQUEUES:
- Run in process context
- CAN sleep (use mutexes, allocate memory)
- More flexible, slightly higher overhead

static void work_handler(struct work_struct *work) {
    // Can sleep here
    msleep(100);
}

DECLARE_WORK(my_work, work_handler);

// Schedule work
schedule_work(&my_work);

// Use cases:
// Tasklet: Quick processing, no blocking needed
// Workqueue: I2C/SPI transfers, memory allocation

What synchronization mechanisms are available in the kernel?

1. SPINLOCKS (busy-wait, interrupt-safe)
spinlock_t lock;
spin_lock_init(&lock);
spin_lock(&lock);
// Critical section
spin_unlock(&lock);

// In interrupt context:
spin_lock_irqsave(&lock, flags);
spin_unlock_irqrestore(&lock, flags);


2. MUTEXES (can sleep, process context only)
struct mutex my_mutex;
mutex_init(&my_mutex);
mutex_lock(&my_mutex);
// Critical section (can sleep)
mutex_unlock(&my_mutex);


3. SEMAPHORES
struct semaphore sem;
sema_init(&sem, 1);
down(&sem);       // Acquire (can sleep)
up(&sem);         // Release


4. ATOMIC OPERATIONS
atomic_t counter = ATOMIC_INIT(0);
atomic_inc(&counter);
atomic_dec(&counter);
int val = atomic_read(&counter);


5. RW LOCKS (multiple readers, single writer)
rwlock_t rwlock;
read_lock(&rwlock);    // Multiple readers OK
read_unlock(&rwlock);
write_lock(&rwlock);   // Exclusive access
write_unlock(&rwlock);
💾 Kernel Memory Management

What are the different ways to allocate memory in the kernel?

1. kmalloc() - Small allocations (< 128KB)
void *ptr = kmalloc(size, GFP_KERNEL);
kfree(ptr);

// GFP flags:
GFP_KERNEL  // Normal allocation (can sleep)
GFP_ATOMIC  // Interrupt context (no sleep)
GFP_DMA     // DMA-capable memory


2. kzalloc() - Zero-initialized
void *ptr = kzalloc(size, GFP_KERNEL);


3. vmalloc() - Large allocations (virtually contiguous)
void *ptr = vmalloc(large_size);
vfree(ptr);
// Note: Not physically contiguous


4. get_free_pages() - Page-aligned allocation
unsigned long addr = __get_free_pages(GFP_KERNEL, order);
// order: 2^order pages
free_pages(addr, order);


5. DMA allocations
void *cpu_addr = dma_alloc_coherent(dev, size, 
                                    &dma_handle, GFP_KERNEL);
dma_free_coherent(dev, size, cpu_addr, dma_handle);


Memory pools for frequent same-size allocations:
struct kmem_cache *cache;
cache = kmem_cache_create("my_cache", sizeof(struct mystruct),
                          0, 0, NULL);
ptr = kmem_cache_alloc(cache, GFP_KERNEL);
kmem_cache_free(cache, ptr);

What is the difference between kmalloc and vmalloc?

kmalloc():
- Physically contiguous memory
- Limited size (typically < 128KB)
- Fast allocation
- Required for DMA operations
- Use for most kernel allocations

vmalloc():
- Virtually contiguous, physically scattered
- Can allocate large buffers (MBs)
- Slower (requires page table setup)
- NOT suitable for DMA
- Use for large buffers not needing physical contiguity

Comparison:
┌────────────────┬──────────────┬──────────────┐
│ Feature        │ kmalloc      │ vmalloc      │
├────────────────┼──────────────┼──────────────┤
│ Phys. contig.  │ Yes          │ No           │
│ Max size       │ ~128KB       │ Large (MBs)  │
│ Speed          │ Fast         │ Slower       │
│ DMA safe       │ Yes          │ No           │
│ Common use     │ Small bufs   │ Large bufs   │
└────────────────┴──────────────┴──────────────┘
🔌 Platform & Device Tree

What is a Platform Driver?

Platform drivers are used for devices that are not discoverable (no bus enumeration). They rely on platform device definitions in device tree or board files. 
static int my_probe(struct platform_device *pdev)
{
    // Device initialization
    struct resource *res;
    res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
    // Map registers, request IRQ, etc.
    return 0;
}

static int my_remove(struct platform_device *pdev)
{
    // Cleanup
    return 0;
}

static const struct of_device_id my_of_match[] = {
    { .compatible = "vendor,my-device" },
    { }
};
MODULE_DEVICE_TABLE(of, my_of_match);

static struct platform_driver my_driver = {
    .probe  = my_probe,
    .remove = my_remove,
    .driver = {
        .name = "my-driver",
        .of_match_table = my_of_match,
    },
};

module_platform_driver(my_driver);

What is Device Tree?

Device Tree is a data structure describing hardware components. It allows a single kernel to support multiple hardware configurations. 
Device Tree Source (.dts):
/dts-v1/;

/ {
    compatible = "vendor,board";
    
    memory@80000000 {
        device_type = "memory";
        reg = <0x80000000 0x20000000>;
    };
    
    my_device@40000000 {
        compatible = "vendor,my-device";
        reg = <0x40000000 0x1000>;
        interrupts = <0 42 4>;
        clocks = <&clk_uart>;
        status = "okay";
    };
};

// Accessing in driver:
static int my_probe(struct platform_device *pdev)
{
    struct device_node *np = pdev->dev.of_node;
    u32 value;
    
    // Read property
    of_property_read_u32(np, "my-property", &value);
    
    // Get resource from reg property
    res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
    
    return 0;
}
🔥 Advanced Topics

What is IOCTL and how is it implemented?

IOCTL (Input/Output Control) allows user space to send commands and data to drivers beyond simple read/write. 
// Define IOCTL commands (in header file)
#define MY_IOC_MAGIC 'k'
#define MY_IOCTL_RESET    _IO(MY_IOC_MAGIC, 0)
#define MY_IOCTL_GET_VAL  _IOR(MY_IOC_MAGIC, 1, int)
#define MY_IOCTL_SET_VAL  _IOW(MY_IOC_MAGIC, 2, int)
#define MY_IOCTL_RW_VAL   _IOWR(MY_IOC_MAGIC, 3, int)

// Driver implementation
static long my_ioctl(struct file *filp, 
                     unsigned int cmd, 
                     unsigned long arg)
{
    int val;
    
    switch (cmd) {
    case MY_IOCTL_RESET:
        // Reset device
        break;
        
    case MY_IOCTL_GET_VAL:
        val = device_value;
        if (copy_to_user((int *)arg, &val, sizeof(val)))
            return -EFAULT;
        break;
        
    case MY_IOCTL_SET_VAL:
        if (copy_from_user(&val, (int *)arg, sizeof(val)))
            return -EFAULT;
        device_value = val;
        break;
        
    default:
        return -ENOTTY;
    }
    return 0;
}

// User space usage:
int fd = open("/dev/mydev", O_RDWR);
ioctl(fd, MY_IOCTL_RESET);
ioctl(fd, MY_IOCTL_GET_VAL, &value);

What is Memory Mapping (mmap) in drivers?

mmap allows user space to directly access device memory/registers without copy operations. 
// Driver mmap implementation
static int my_mmap(struct file *filp, 
                   struct vm_area_struct *vma)
{
    unsigned long size = vma->vm_end - vma->vm_start;
    unsigned long pfn = device_phys_addr >> PAGE_SHIFT;
    
    // Disable caching for hardware registers
    vma->vm_page_prot = pgprot_noncached(vma->vm_page_prot);
    
    if (remap_pfn_range(vma, vma->vm_start, pfn,
                        size, vma->vm_page_prot))
        return -EAGAIN;
    
    return 0;
}

// User space usage:
int fd = open("/dev/mydev", O_RDWR);
void *addr = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                  MAP_SHARED, fd, 0);

// Direct register access
volatile uint32_t *regs = (uint32_t *)addr;
regs[0] = 0x1234;  // Write to register

munmap(addr, 4096);
close(fd);

📝 Multiple Choice Questions

Which function is used to copy data from user space to kernel space?

  • A) memcpy()
  • B) copy_from_user()
  • C) copy_to_user()
  • D) kmalloc()
Answer: B - copy_from_user() safely copies data from user space to kernel space, handling potential page faults.

What is the first process started by the Linux kernel (PID 1)?

  • A) kernel
  • B) bash
  • C) init/systemd
  • D) getty
Answer: C - init (or systemd on modern systems) is the first userspace process, responsible for starting all other services.

Which memory allocation function provides physically contiguous memory?

  • A) kmalloc()
  • B) vmalloc()
  • C) malloc()
  • D) alloc()
Answer: A - kmalloc() allocates physically contiguous memory, required for DMA operations. vmalloc() provides only virtually contiguous memory.

What synchronization mechanism should be used in interrupt context?

  • A) mutex
  • B) semaphore
  • C) spinlock
  • D) wait queue
Answer: C - Spinlocks must be used in interrupt context because mutexes and semaphores can sleep, which is not allowed in interrupt handlers.

Which type of device driver provides sequential byte-stream access?

  • A) Character driver
  • B) Block driver
  • C) Network driver
  • D) Platform driver
Answer: A - Character drivers provide sequential access to data as a stream of bytes. Block drivers provide random access in fixed-size blocks.

What does GFP_ATOMIC flag mean in kmalloc()?

  • A) Allocate from high memory
  • B) Don't sleep during allocation
  • C) Allocate DMA-capable memory
  • D) Zero-initialize memory
Answer: B - GFP_ATOMIC is used when the allocation cannot sleep (in interrupt context or while holding spinlocks).

Which directory contains information about running processes?

  • A) /sys
  • B) /proc
  • C) /dev
  • D) /var
Answer: B - /proc is a virtual filesystem containing process and kernel information. /proc/[PID]/ contains info about each process.

What is the purpose of device_create() function?

  • A) Allocate memory for device
  • B) Register file operations
  • C) Create device node in /dev
  • D) Initialize device hardware
Answer: C - device_create() automatically creates the device node file in /dev (with udev), so users don't need to manually use mknod.

Which bottom-half mechanism can sleep?

  • A) Tasklet
  • B) Softirq
  • C) Workqueue
  • D) None of the above
Answer: C - Workqueues run in process context and can sleep. Tasklets and softirqs run in software interrupt context and cannot sleep.

What is the purpose of __init macro in kernel modules?

  • A) Mark function as interrupt handler
  • B) Mark function to be discarded after init
  • C) Initialize static variables
  • D) Make function thread-safe
Answer: B - __init marks initialization functions that can be freed after module loading, saving memory.

What is the difference between request_irq() and devm_request_irq()?

  • A) devm version is faster
  • B) devm version is automatically freed on driver removal
  • C) devm version supports shared interrupts
  • D) No difference
Answer: B - devm_ (device-managed) functions automatically clean up resources when the device is removed, preventing memory leaks.

Which macro is used to define IOCTL commands for reading data?

  • A) _IO()
  • B) _IOR()
  • C) _IOW()
  • D) _IOWR()
Answer: B - _IOR() defines commands that read data from the driver (R = read). _IOW() is for writing, _IOWR() for both, _IO() for no data.
